# Task: Property-based tests for the mutation and acceptance invariants

## Description

Replace "we tested five examples" with "the invariant holds for generated inputs, with a
reproducible seed when it does not". The properties target the places where this codebase's
real risk sits: segment boundaries in the pooled pipe, UTF-8 validation that must carry partial
sequences across segments, and a suffix writer that must never write past its span.

## Context for the implementer

Library: the one ADR-0010 settles (proposed: CsCheck). Read ADR-0010 before starting.

Public surface under test, all without ASP.NET Core types:

- `MutationPolicy.GetRequiredByteCount(in MutationContext)` and
  `MutationPolicy.TryWriteSuffix(Span<byte>, in MutationContext, out int)` in
  `src/FileMutation.Domain/MutationPolicy.cs`. Suffix format is `\nyyyy-MM-dd:sequence`.
- `FileName.TryCreate(string?, out FileName?)` in `src/FileMutation.Domain/FileName.cs`.
- `FileAcceptance.Evaluate(ReadOnlySpan<byte>, ...)` and
  `FileAcceptance.Evaluate(in ReadOnlySequence<byte>, ...)` in
  `src/FileMutation.Application/FileAcceptance.cs`.
- The mutator adapter exercised by `tests/FileMutation.Infrastructure.Tests/FileMutatorAdapterTests.cs`.

Deterministic fakes (`FixedTimeProvider`, `FixedRandomSequenceGenerator`) live in
`tests/FileMutation.TestCommon/DeterministicFakes.cs`. Use them; do not add new fakes.

Properties to implement:

| # | Property |
|---|---|
| P1 | For any context and any destination length: `TryWriteSuffix` returns true and writes exactly `GetRequiredByteCount` bytes when the span is large enough; otherwise returns false and writes 0 bytes |
| P2 | The written suffix always decodes as UTF-8 and matches `\nyyyy-MM-dd:` followed by the sequence |
| P3 | Split invariance: for any byte content and any partition of it into segments, `Evaluate(sequence)` equals `Evaluate(span)` |
| P4 | Valid UTF-8 (generated, including 2-, 3- and 4-byte characters) with accepted metadata is accepted; the same content with one byte replaced by an invalid lead or continuation byte is rejected as `InvalidUtf8` |
| P5 | Mutation preserves the prefix: output equals input bytes followed by the suffix, for any content and any segment partition |
| P6 | `FileName.TryCreate` either fails, or yields a value with no path separator or control character, and re-creating from that value yields the same value (idempotent) |

## Pre-mortem

**Most likely failure:** the generators only produce ASCII content or single-segment
sequences, so P3 and P5 pass without ever placing a multi-byte character across a segment
boundary. The suite goes green and proves nothing, which is worse than no property because it
gets cited.

**Early signal:** a distribution check (CsCheck `Classify` or an explicit counter) shows that
fewer than 20% of P3 cases split a multi-byte character across a boundary.

**Kill criterion:** if the library cannot generate segmented `ReadOnlySequence<byte>` values,
build segments in a small test helper; do not drop P3 or P5. If a property cannot be made to
fail against a planted bug, it is removed, not kept.

## Acceptance Criteria
- [ ] P1–P6 implemented and running inside `dotnet test`, so they count toward the coverage gate
- [ ] A failing property prints its seed, and re-running with that seed reproduces the failure
- [ ] Generator distribution for P3 shows at least 20% of cases split a multi-byte character across a segment boundary (reported in the PR)
- [ ] Each property is shown to fail against a planted bug (off-by-one in segment copy, suffix length miscount, a UTF-8 check that resets state per segment); the plants and their failing output are listed in the PR description and not committed
- [ ] Total property-test runtime under 10 s in CI (iteration counts set explicitly, not left at defaults)
- [ ] No existing example test deleted unless a property strictly subsumes it, and each deletion is named in the PR
- [ ] Branch coverage not lower than before
