# Task: ADR-0010 — bring property-based, Gherkin and mutation testing into scope

## Description

Record the decision to add three verification layers that v0.1 excluded, and update every
document that still says they are out of scope. No code and no package references in this
task: the decision lands first so the tasks that implement it are not contradicting the repo's
own rules while they run.

## Context for the implementer

Three places currently forbid this work:

- `.claude/prds/file-mutation-api.md`, out-of-scope table: the "Gherkin / BDD test layer" and
  "Stryker.NET mutation testing" rows, each with a stated reason.
- `.claude/rules/dotnet-conventions.md`, "Out of scope — do not build these": lists "Gherkin
  tests, Stryker mutation testing" and says "stop and ask".
- `docs/adr/0007-testing-strategy.md`: the testing strategy names xUnit, WebApplicationFactory,
  branch coverage and BenchmarkDotNet only.

The reversal needs a reason that names a **defect class the current suite cannot detect**, per
layer. "It looks thorough" is not a reason. Candidate reasons, to be confirmed or rejected:

- Mutation testing: branch coverage proves a branch executed, not that an assertion would fail
  if the branch computed the wrong value. For an agent-assisted codebase this is precisely the
  reviewer's question: do these tests test anything?
- Property-based: the hard bugs here live at pipe-segment boundaries (a multi-byte UTF-8
  character split across segments). Example tests pick a few split points; a property covers
  all of them.
- Gherkin: US-1 and US-2 acceptance criteria exist only as PRD prose. Scenarios make each one
  executable and readable by the product owner, and traceable by tag.

Library facts checked on 2026-09-28 (re-check on the day the ADR is written):

| Package | Latest stable | Licence | Note |
|---|---|---|---|
| `CsCheck` | 4.9.1 | Apache-2.0 | C#-native API, targets net8.0, integrated shrinking |
| `FsCheck` / `FsCheck.Xunit` | 3.4.0 | BSD-3-Clause | F# core; the alternative to record |
| `Reqnroll` / `Reqnroll.xUnit` | 3.3.4 | BSD-3-Clause | SpecFlow successor; `Reqnroll.xUnit` depends on `xunit.core` 2.8.1, compatible with the repo's xunit 2.9.3 |
| `dotnet-stryker` | 5.0.0 (2026-09-11) | Apache-2.0 | 5.0.0 targets the .NET 10 runtime |

The built-in-before-third-party rule in `AGENTS.md` exists because shipped packages must be
trim-safe for Native AOT. All three tools are test-time only and never ship, so the ADR states
that exemption explicitly rather than leaving a reader to wonder.

## Pre-mortem

**Most likely failure:** the ADR reads as a retroactive justification (tools added because they
look thorough) rather than a decision, and a reviewer discounts the whole epic because of it.

**Early signal:** for any layer, the Context section cannot name a concrete defect the current
suite would miss.

**Kill criterion:** if no concrete defect class can be named for a layer, drop that layer from
the epic and close its story as not planned. Do not build a layer the ADR cannot justify.
