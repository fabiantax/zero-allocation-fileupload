# Task: Batch event contracts and the channel event publisher

## Description

Land the Domain types every later story compiles against, plus the one adapter that makes the
new port real. Architecture rules require a port to ship with an implementation and a
registration, so the port cannot land alone.

## Context for the implementer

- Copy the Domain section of `.claude/epics/bulk-and-events/contracts.md` verbatim:
  `Batches/BatchId.cs`, `Batches/BatchFileOutcome.cs` (with `BatchFileStatus`),
  `Events/*.cs` (one file per record plus `IEventHandler.cs`), `Ports/IEventPublisher.cs`.
- `tests/FileMutation.Architecture.Tests/PortRules.cs` builds a provider with only
  `TimeProvider` plus `AddFileMutationInfrastructure()` and resolves every port. So
  `ChannelEventPublisher` must resolve from that alone: take `EventBusOptions` directly (register
  a default instance with `TryAddSingleton`), no `IOptions`, no `ILogger`.
- Publisher design: one unbounded `Channel<BatchEvent>` (a single FIFO keeps per-batch order)
  plus an `Interlocked` count of queued non-terminal events. At `Capacity`, a non-terminal
  event is dropped, counted in a `System.Diagnostics.Metrics` counter
  (`filemutation.events.dropped`) and `TryPublish` returns false. Terminal events are always
  written. Expose the `ChannelReader<BatchEvent>` for story 003 through the public
  `IEventStream` interface registered in DI (see `contracts.md`); the adapter itself stays
  internal. `InternalsVisibleTo` is not allowed.
- `BatchId.New()` uses `RandomNumberGenerator.GetHexString(32, lowercase: true)`.
- New arch rules in `EventRules.cs`: event records live in `FileMutation.Domain.Events` and are
  sealed or abstract; nothing in Domain references `System.Threading.Channels`.

## Pre-mortem

**Most likely failure:** the capacity check and the write race, so under concurrent publishers
the queue exceeds capacity or a terminal event is counted against it.

**Early signal:** a concurrent test (8 publishers, capacity 16) sees more than 16 non-terminal
events queued.

**Kill criterion:** if a lock-free version is not correct in 45 minutes, use a `lock`; the
publisher is not on a measured hot path.
