# Task: Batch mutation session: per-file outcomes, chunk and batch events

## Description

The transport-free core of bulk upload: take files one at a time, run each through the existing
single-file service, record an outcome row, and publish the events that let handlers chain after
a file, a chunk, or the batch.

## Context for the implementer

- Signatures: `.claude/epics/bulk-and-events/contracts.md`, Application section.
- `BatchMutationService(ISingleFileMutationService, IEventPublisher, TimeProvider)` implements
  `IBatchMutationService`. Composition only: it calls
  `ISingleFileMutationService.MutateAsync` per file and never touches `IFileMutator`
  (`IFileMutator` backs the published benchmark and does not change).
- One file in memory at a time: `MutateNextAsync` returns a `BatchFileResult` that owns the
  pooled content; the caller writes it and disposes it before asking for the next file. The
  session keeps only `BatchFileOutcome` rows.
- Reason codes: `FileMutationFailureReason` / `FileRejectionReason` member names (e.g.
  `UnsupportedFileExtension`, `TooLarge`), plus `BatchFileLimitExceeded` for files past
  `MaxFiles`. `MutationFailed` is a rejected row, not an exception (the single-file endpoint
  turns it into a 500; a batch must not lose the other files).
- Entry-name dedup rule and chunk rule: see `contracts.md`. Sequence numbers start at 1 per
  batch, strictly increasing, no gaps at the source.
- `Abort` after `Complete` is ignored; `DisposeAsync` without either publishes `BatchAborted`
  with `Disposed`.

## Pre-mortem

**Most likely failure:** outcomes are collected together with their content "for convenience",
so memory grows with the batch and the one-file-in-memory claim silently breaks.

**Early signal:** any `List<BatchFileResult>` or retained `Stream` field in the session.

**Kill criterion:** story 008's benchmark is the proof; if per-file allocation is not flat from
1 to 100 files, this story's design is reopened, not the benchmark's.

## Acceptance Criteria
- [ ] 3 files (valid, `.json`, valid) give outcomes Mutated, Rejected(`UnsupportedFileExtension`), Mutated and events FileMutated, FileRejected, FileMutated, then BatchCompleted(2, 1) on `Complete`
- [ ] ChunkSize 2 with 5 files publishes chunks (1, 2 files), (2, 2 files), (3, 1 file) before BatchCompleted
- [ ] Two `a.txt` become `a.txt` and `a (2).txt`; `A.TXT` after them becomes `A (3).TXT`
- [ ] File MaxFiles+1 is rejected with `BatchFileLimitExceeded` without reading its content
- [ ] A mutator that throws on file 2 yields a Rejected(`MutationFailed`) row and files 1 and 3 still succeed
- [ ] Dispose without Complete publishes exactly one BatchAborted(`Disposed`); Abort after Complete publishes nothing
- [ ] Sequence numbers are 1..n with no gaps
- [ ] Each new test fails against a planted defect (listed in the PR)
