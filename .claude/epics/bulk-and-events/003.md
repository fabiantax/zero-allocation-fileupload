# Task: Background event dispatcher and AddEventHandler

## Description

The chaining mechanism: a caller registers `services.AddEventHandler<BatchCompleted, MyHandler>()`
and `MyHandler` runs after every completed batch. The dispatcher must isolate handlers from the
upload path and from each other.

## Context for the implementer

- Signatures: `.claude/epics/bulk-and-events/contracts.md`, Infrastructure section (story 003).
- `EventDispatcherService : BackgroundService` reads the channel exposed by story 001 and, for
  each event, invokes every registration whose `TEvent` matches the runtime type.
- Registration without reflection: `AddEventHandler<TEvent, THandler>` adds a closed
  `EventSubscription<TEvent>` (internal) that knows how to cast and call `THandler`; the
  dispatcher holds `IEnumerable<IEventSubscription>` and asks each `CanHandle(BatchEvent)`.
  No `MakeGenericType`, no assembly scanning.
- Isolation: each handler call runs in its own `try/catch`. Since .NET 6 an unhandled exception
  in `ExecuteAsync` stops the host by default (`BackgroundServiceExceptionBehavior.StopHost`),
  so one escaped exception would take the API down. Failures are logged with `ILogger` and
  counted (`filemutation.events.handler_failures`).
- Handlers run sequentially per event, in registration order; a slow handler delays later
  events but never the publisher (the channel absorbs it, story 001's capacity applies).
- Add `Microsoft.Extensions.Hosting.Abstractions` and `Microsoft.Extensions.Logging.Abstractions`
  10.0.12 to the Infrastructure project (both built-in, MIT; version exists on nuget.org,
  checked 2026-09-29).

## Pre-mortem

**Most likely failure:** the handler exception is caught, but an exception from
`CanHandle`/resolution or a cancelled token during shutdown escapes `ExecuteAsync` and stops the
host anyway.

**Early signal:** a test host with a throwing handler reports `IHostApplicationLifetime.ApplicationStopping`.

**Kill criterion:** if shutdown ordering cannot be made clean in 45 minutes, document the gap in
the PR and file it; do not swallow `OperationCanceledException` globally.

## Acceptance Criteria
- [ ] A handler that throws is logged and counted; the next handler and the next event still run; the host keeps running
- [ ] A handler that awaits 5 s does not delay `TryPublish` (publisher returns in under 50 ms)
- [ ] Handlers for a base type are not invoked for other types; each registration receives only its `TEvent`
- [ ] Registering the same handler type for five event types yields one instance
- [ ] Events for one batch reach a handler in sequence order
- [ ] Each new test fails against a planted defect (listed in the PR)
