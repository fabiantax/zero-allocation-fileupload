# Task: ADR-0011 and ADR-0012: bulk contract, batch events and the read model

## Description

Record the decisions before any code references them. Bulk upload and batch events reverse or
amend four recorded positions (see the table in `epic.md`); the repo's practice is that the ADR
lands first and every implementation story depends on it.

## Context for the implementer

- Read `docs/adr/0002-cqrs-mediator-choice.md` in full, especially the addendum "when a mediator
  earns its keep". Apply its arithmetic honestly: v0.3 has 3 use cases (mutate file, mutate
  batch, get batch status) and 1 shared concern (event publication is not a pipeline behavior).
  The line is 3 use cases **and** 2 concerns, so ADR-0002's "no mediator" stands. Events are a
  separate question the addendum already answers: they earn their keep once a real listener
  exists, and `BatchStatusProjection` is that listener.
- ADR-0011 (bulk contract): streamed ZIP plus `manifest.json` as the last entry; partial
  success as manifest rows; request-level checks before the first byte (amends ADR-0005's
  two-phase rule for the batch endpoint only; the single-file endpoint keeps it); limits table from
  `contracts.md`; a concurrency limiter on the batch endpoint only (reverses the PRD's
  "rate limiting: not implemented" for this endpoint, with the reason); duplicate-name rule;
  what happens after the status is committed (abort the connection, `BatchAborted`).
- ADR-0012 (events and read model): event list, at-most-once in-process delivery, terminal
  events never dropped, per-batch sequence numbers, handler isolation (BackgroundService
  defaults to `StopHost` on an unhandled exception), in-memory bounded read model (ADR-0008
  unchanged), durable chaining explicitly out of scope, content-processing steps (handlers that
  need file bytes) out of scope with the reason: bytes are gone when events run.
- Follow the format of `docs/adr/0008-persistence-deferral.md`. Add both to `docs/decision-log.md`.
- PRD `.claude/prds/file-mutation-api.md`: add a "v0.3 (self-set extension, not a client
  requirement)" section with US-4, US-5, US-6 and their acceptance criteria (copy from
  `epic.md` and `contracts.md`), plus a v0.3 out-of-scope table (durable delivery, content
  steps, metrics listener, auth, async 202 download).

## Pre-mortem

**Most likely failure:** ADR-0012 quietly re-justifies a mediator by counting event publication
as a cross-cutting concern, and a later post or reviewer catches the bent arithmetic.

**Early signal:** ADR-0012 uses the words "mediator", "Send" or "pipeline behavior" as things
v0.3 adopts.

**Kill criterion:** if the honest count cannot support events without a mediator, stop and
report instead of writing the ADR.
