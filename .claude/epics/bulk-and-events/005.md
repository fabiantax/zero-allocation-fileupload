# Task: Streamed ZIP response writer with a manifest

## Description

Write mutated files into a ZIP directly on the response body, one entry at a time, and finish
with `manifest.json`. This is the riskiest mechanism in the epic, so it starts with a spike.

## Context for the implementer

- Signatures: `.claude/epics/bulk-and-events/contracts.md`, Api section (story 005), and the
  manifest JSON shape there.
- The response body is non-seekable and Kestrel forbids synchronous IO by default
  (`AllowSynchronousIO = false`). A `ZipArchive` in `Create` mode that flushes or writes its
  central directory synchronously throws `InvalidOperationException` under Kestrel. The
  .NET 10.0.12 reference pack has `ZipArchive.CreateAsync(Stream, ZipArchiveMode, bool,
  Encoding, CancellationToken)`, `ZipArchiveEntry.OpenAsync(CancellationToken)` and
  `ZipArchive.DisposeAsync` (checked 2026-09-29).
  **Spike first**: prove with a test server (`TestServer` with `AllowSynchronousIO = false`)
  that a 3-entry archive streams and opens with `ZipFile.OpenRead`.
- Compression: `CompressionLevel.Fastest` for entries; the manifest the same.
- Manifest serialization: a new source-generated `BatchManifestJsonContext`
  (`System.Text.Json`, camelCase, enums as camelCase strings) in `src/FileMutation.Api/Batches/`.
  No reflection-based serializer.
- Test the Scalar UI question here as well: open `/openapi/v1.json` and record whether a
  multipart array of binary files is described in a way Scalar renders as a multi-file picker.
  Write the finding in the PR; story 006 uses it.

## Pre-mortem

**Most likely failure:** a synchronous write hides in `Dispose` (central directory) and only
shows under Kestrel, not in a `MemoryStream` unit test.

**Early signal:** the spike passes with `MemoryStream` but was never run against a stream that
throws on synchronous `Write`/`Flush`.

**Kill criterion:** if async ZIP on a non-seekable stream cannot be made fully async in 60
minutes, stop and report with the stack trace; the fallbacks (buffer the archive, or a
stored-only hand-written ZIP writer) change ADR-0011 and need a decision.

## Acceptance Criteria
- [ ] Tests write through a stream wrapper that throws on any synchronous `Write`, `Flush` or `Dispose` and pass
- [ ] A 3-entry archive written to a non-seekable stream opens with `ZipFile.OpenRead`, entries in write order, `manifest.json` last
- [ ] Manifest JSON matches the shape in `contracts.md`, including `complete: false` when written after an abort
- [ ] The Scalar multi-file finding is recorded in the PR description
