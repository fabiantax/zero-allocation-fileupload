# Task: Native AOT publish profile + startup/size measurements

## Description

> **Contingent on task 000.** Task 000's spike ADR (`docs/adr/0001-native-aot.md`) decides whether AOT is adopted or dropped. If it concluded AOT is dropped, this task is closed as not-applicable rather than executed. Do not start any part of this task before 000 is resolved.

Finish the AOT story the skeleton started: make an AOT publish part of the build, prove the whole solution (not just the host) is trim- and AOT-clean, and record what it buys.

Task 000 proves AOT is *possible* with the chosen packages. This task makes it real across every project and measures the result.

## Context for the implementer

This depends on task 000's decision — see the note above before starting anything. "Verified by running the integration test suite against it" can't mean the existing `WebApplicationFactory`-based tests in `FileMutation.Api.Tests`: `WebApplicationFactory` boots the app in-process from the built assembly, so it never touches the published native executable. Run the published binary as its own process and point HTTP-based tests at it instead. Cold-start numbers from a single run are noise, not evidence — average several runs, as noted below.

## Do not

- Do not start this task before task 000's ADR is merged and confirms AOT is adopted.
- Do not "verify" the published binary with `WebApplicationFactory` — that exercises the in-process app, not the AOT executable.
- Do not work around an AOT-hostile dependency with reflection-enabling switches — record it in the ADR instead, per task 000's rule.

## Technical Details

- Native AOT is platform-specific: publish per RID (`osx-arm64` locally, `linux-x64` in CI) — there is no portable AOT output
- Reflection-based paths are what break AOT; the source-generated `JsonSerializerContext` from 001 covers serialisation, and `MultipartReader` (task 004) avoids reflective form binding
- Startup measurement should be an average over several runs — a single cold start on a loaded machine is noise, not evidence
- If a dependency turns out to be AOT-hostile, record it in the ADR rather than working around it with reflection-enabling switches that silently degrade the result
