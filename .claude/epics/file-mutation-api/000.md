# Task: Spike — does Native AOT publish with OpenAPI + Scalar?

## Description

Settle one question by running it, before anything is built on top: **can this stack publish
with `PublishAot=true` while still serving a browser OpenAPI UI?**

This is a spike, not a feature. It exists because the answer changes the package choice for
every later task, and the package choice is expensive to reverse once endpoints are
documented against it. Throwaway code is the expected output — the deliverable is the
decision.

**Timebox: 1 hour.** If it is not settled by then, that is itself the answer: drop AOT,
record why, and proceed. Do not spend a day making it work.

## Context for the implementer

The ticket requires a Swagger-style UI. If AOT and a working UI genuinely conflict, **the UI
requirement wins and AOT is dropped** — AOT is our idea, the UI is the client's requirement.

Swashbuckle is already ruled out (reflection-based, blocks AOT). The candidate stack is the
built-in `Microsoft.AspNetCore.OpenApi` for the document plus `Scalar.AspNetCore` for the UI.

## Files

Scratch only — build this outside `src/`, e.g. in a temp directory. Nothing from this task
is merged except `docs/adr/0001-native-aot.md`.

## Acceptance Criteria
- [ ] A throwaway minimal API with `Microsoft.AspNetCore.OpenApi` + `Scalar.AspNetCore`
      publishes with `dotnet publish -c Release -r osx-arm64 -p:PublishAot=true`
- [ ] The published native binary runs and serves the UI in a browser — verified, not assumed
- [ ] Trim/AOT warnings recorded (count and IDs), even if the publish succeeds
- [ ] `docs/adr/0001-native-aot.md` written: what was tried, what happened, decision (adopt
      or drop), and which packages the rest of the epic must use
- [ ] If AOT is dropped: task 011 is closed as not-applicable and the epic's AOT decision
      section updated to say so

## Verify with

```bash
dotnet publish -c Release -r osx-arm64 -p:PublishAot=true
./bin/Release/net10.0/osx-arm64/publish/<app>   # then open the UI in a browser
```

## Do not

- Do not build any project structure, domain types, or real endpoints here.
- Do not work around an AOT failure with reflection-enabling switches — that silently
  degrades the result and hides the problem from later tasks.
