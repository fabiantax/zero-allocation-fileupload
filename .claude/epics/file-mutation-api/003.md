# Task: Pipelines-based mutation engine

## Description

Implement `IFileMutator`: stream the uploaded content through and append the current UTC date plus a random character sequence, without buffering the whole file into memory. This is where the zero-allocation claim is earned.

## Context for the implementer

- This is plumbing only: `DateAndRandomSequenceMutator` must call the pure mutation policy function defined in Domain (task 002), not reimplement the "append date + random sequence" rule against `Span<byte>` itself. If you find yourself writing the formatting logic here instead of calling into `FileMutation.Domain`, stop — that duplicates a business rule across layers, which the Definition of Done explicitly forbids.
- The policy's signature comes from 002 as a given — adapt `ReadOnlySequence<byte>`/`PipeWriter` on this side to fit it; don't change the Domain signature to suit the Pipelines code.
- Segment-boundary handling is the actual point of this task (see the required test). A naive implementation that assumes a single-segment `ReadOnlySequence` will pass every other test and quietly fail only that one.

## Pre-mortem

**Most likely failure:** The multi-segment path is written against a single-segment `ReadOnlySequence` and every test still passes, because small test inputs never split. The bug ships and only appears on a file large enough to straddle a segment.

**Early signal:** The required boundary test passes on the first attempt without the implementation ever handling a carry. If it goes green immediately, suspect the *test*, not the code — assert it fails against a deliberately naive implementation first.

**Kill criterion:** `dotnet test` hangs past ~30s: that is the sandbox blocking the VSTest host socket, not slow tests. Kill it and re-run with the sandbox bypassed rather than debugging the code.

## Acceptance Criteria

- [ ] Writes through pooled `Pipe` segments only — a test asserts no single buffer reaches the 85,000-byte LOH threshold, whatever the file size
- [ ] Content is streamed via `System.IO.Pipelines`; no `ReadAllBytes`/`ReadAllText`/whole-file `MemoryStream`

- [ ] Tests in `FileMutation.Infrastructure.Tests`: empty file, single-byte file, multi-segment buffer, content crossing a pipe segment boundary

## Do not

- Do not reimplement the append-date-and-random-sequence rule here — call the Domain mutation policy from 002; this layer is plumbing only.
- Do not buffer the whole file (`ReadAllBytes`, whole-file `MemoryStream`) to sidestep multi-segment handling.
- Do not call `DateTime.UtcNow`/`Random` directly — both must come in via the injected `TimeProvider`/`IRandomSequenceGenerator`.

## Technical Details

- Work over `ReadOnlySequence<byte>` from `PipeReader.ReadAsync`; handle multi-segment sequences explicitly (the segment-boundary test exists to prove this)
- Write output through `PipeWriter`, using `GetSpan`/`Advance` rather than intermediate arrays
- Date and random sequence are formatted into a stack `Span<char>`/`Span<byte>` (`TryFormat`) instead of interpolated strings
- Pool anything that must be rented; nothing on the hot path should reach the LOH
