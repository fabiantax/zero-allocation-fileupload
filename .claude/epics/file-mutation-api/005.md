# Task: Local-disk repository adapter

## Description

**DEFERRED — do not start.** This task is blocked on PRD open questions OQ-1 (is persistence needed at all?) and OQ-2 (is an audit trail required?). Nothing else in the epic depends on 005, so leaving it deferred costs nothing. Do not begin implementation until OQ-1/OQ-2 are answered — if OQ-1 comes back "yes, persist and retrieve", this task is rewritten rather than adjusted, so starting early risks throwaway work.

Implement `IFileRepository` against the local filesystem. Scoped deliberately small: the ticket requires no persistence (PRD OQ-1), so this exists to prove the port is real and swappable, not to build a storage subsystem.

If OQ-1/OQ-2 come back requiring persistence or an audit trail, that adapter replaces this one without touching Domain, Application, or Api.

## Context for the implementer

`IFileRepository` already exists as a port from 002 (persist + retrieve by id) — this task only implements it, it does not design it. The settled decision is no database: no EF Core, no SQLite, even though a repository adapter naturally invites one — that would commit to a schema before OQ-1 is answered. The likely trap is treating `parallel: true` / `depends_on: [2]` as "unblocked" — `status: blocked` overrides that; check status before claiming this task. `Guid.CreateVersion7()` is built into .NET 9+, no extra package needed for time-ordered ids.
