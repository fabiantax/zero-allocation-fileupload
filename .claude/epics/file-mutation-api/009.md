# Task: Evaluate CQRS mediator options and record the decision

## Description

The ticket says to "explore CQRS patterns (e.g. MediatR) if applicable". This task settles which mediator option — if any — the codebase should use, and writes down why. It is evaluation only: no code ships from this task. The winner gets built out on its own branch in task 013, once this decision exists for it to implement.

Compare three options: MediatR (commercial licence since v13, Community tier free under $5M revenue), a hand-rolled `IRequest`/`IRequestHandler` dispatcher, and Wolverine. Write an ADR recording which one wins and why.

There is only one command and one accepted format, so there is no dispatch question to answer — which is itself part of the finding. Say so explicitly rather than leaving a reader to wonder whether it was overlooked.

## Context for the implementer

Task 013 depends on this decision — its acceptance criteria can't be written until this ADR names a winner, so treat the ADR as the actual deliverable, not a formality before "the real work". Cite MediatR's licence by version (commercial since v13, Community tier free under $5M revenue) rather than just "MediatR is free" — that's the detail a future reader will want confirmed. Wolverine is a full messaging framework (sagas, out-of-process transport, etc.); evaluate only its in-process command-handling surface here or the comparison balloons past what this decision needs. The simple `IFileMutationService` still ships to `main` regardless of which mediator wins this comparison — this task doesn't change what ships.
