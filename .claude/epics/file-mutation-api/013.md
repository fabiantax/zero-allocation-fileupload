# Task: Implement the chosen CQRS mediator on a variant branch

## Description

Build the CQRS variant using whichever option task 009 selected, on its own branch, as a
working alternative to the simple service that ships on `main`.

Split from 009 because the implementation cannot be specified before the evaluation picks a
winner — writing acceptance criteria for "implement the chosen one" requires knowing which
one that is.

## Context for the implementer

Read `docs/adr/` for 009's decision before starting. The simple `IFileMutationService` path
stays on `main` — this branch is the counterfactual a reviewer can diff against, not a
replacement.

The point being demonstrated is judgment: both approaches work, and the simpler one ships
because a single command with no divergent read model gains nothing from mediator
indirection. Do not "improve" the variant into the better option.

## Files

Branch `feature/cqrs-variant` only:
- `src/FileMutation.Application/` — command + handler replacing the use-case service
  (one command type per accepted format, per 009's ADR — today that means exactly one)
- `src/FileMutation.Api/Program.cs` — composition root wiring

## Acceptance Criteria
- [ ] The option selected in 009's ADR is implemented on `feature/cqrs-variant`
- [ ] **The same test suite passes unchanged against both variants** — behaviour is
      identical, only composition differs. If a test needs changing, the abstraction leaked.
- [ ] Domain and Infrastructure are untouched by this branch — the diff is confined to
      Application and the composition root. That containment is itself the evidence the
      ports were drawn correctly.
- [ ] The handler delegates to the same `IFileMutator` adapter `main` uses; mutation logic is
      not reimplemented on this branch. If it were, the unchanged-test-suite criterion above
      would be passing for the wrong reason.
- [ ] PR opened and left open (not merged) so the two approaches can be diffed
- [ ] PR description links the ADR and states plainly why this is not what ships

## Verify with

```bash
git diff main...feature/cqrs-variant --stat   # expect changes only in Application + Api
dotnet test                                    # same suite, unchanged, must pass
```

## Do not

- Do not merge this to `main`.
- Do not modify shared test code to make the variant pass — that would hide exactly the
  coupling this task exists to expose.
